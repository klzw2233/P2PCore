# 信任层不含任何线上协议

信任层完全是本地逻辑,**不定义、不收发任何网络消息**。SAS 由两端各自本地计算,验证通过人的带外比对完成,Trust State 只存在于本地。

## 为什么记录这个决定

这是一个容易被"顺手补上"的缺口。总会有人提出:建连之后发一条消息告诉对方"我已经验证过你了",这样双方界面上都能显示已验证。需求听起来完全合理,而拒绝它的理由并不显然。

## 推导

信任层之所以能不需要协议,是三个已有决定叠加的结果:Peer ID 本身就是公钥,所以无需查询;SAS 由双方各自从两个公钥推导,必然相同,所以无需交换;Trust State 是本地判断,所以无需同步。

而"零协议"带来的安全收益是成倍的,不是线性的:

- 零协议解析代码 → 零解析漏洞
- 无版本协商 → **降级攻击面直接消失**(威胁模型 c 中最难防的一类)
- 无线上状态机 → 无状态机混淆攻击
- 无需模糊测试 → 省下一整条测试基础设施

换来的代价只是"对方不知道你验证了他"——纯粹的 UX 糖。

## 后果

- **"已互相验证"的双向展示不由核心库提供。** 需要它的应用在自己的业务协议里发一条消息即可,那是应用层的语义,与信任判断无关。
- **日后任何往信任层加线上协议的提议,都必须先论证它重新打开的攻击面。** 一旦加入第一条消息,上面列举的四项收益会同时消失,而不是只损失一项。
- 信任层没有需要 fuzz 的输入面。若将来引入了模糊测试目标,说明本决定已被推翻,应更新本 ADR。
