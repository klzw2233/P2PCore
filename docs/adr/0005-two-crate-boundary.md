# 拆成两个 crate,用编译器强制分层边界

代码组织为一个 workspace,含两个 crate:

- **`p2p-trust`** — 信任层纯逻辑。其 `Cargo.toml` **不得依赖 iroh、tokio 或任何网络库**。
- **`p2p-core`** — 把信任层接到 iroh 上,提供对外 API。

## 为什么记录这个决定

对一个规模不大的库来说,两个 crate 看起来是过度设计。未来某个人会为了省事把它们合并,而合并的那一刻,[0002](./0002-transport-on-iroh.md) 承诺的"传输层可替换"就悄无声息地失效了——没有任何编译错误会提醒他。

## 推导

[0002](./0002-transport-on-iroh.md) 要求"分层边界必须是硬的"。在 Rust 里,**crate 边界是唯一由编译器强制的边界**。模块划分靠自律:`mod trust` 内部随时可以写 `use iroh::EndpointId`,编译通过,review 时也未必有人注意到。而一个 `Cargo.toml` 里没有 iroh 的 crate,做同样的事会直接编译失败。

考虑过的替代方案是单 crate 加模块分层,或用 feature flag 隔离。两者都依赖人的自觉,而这条边界的价值恰恰在于它在无人看管时依然成立。

附带收益同样实在:`p2p-trust` 零网络依赖,意味着威胁模型要求的那批对抗性测试全部是纯函数测试,毫秒级完成,无需网络环境,在任何平台上都能跑。

## 后果

- **`p2p-trust/Cargo.toml` 新增任何网络或异步运行时依赖,都是边界已被打穿的信号。** CI 应当断言这一点(检查其依赖树),而不是依赖 review。
- `p2p-trust` 是同步的纯逻辑,`p2p-core` 是 async。两者的运行时特性不同,这本身就是边界正确的旁证。
- 更换传输层时,`p2p-trust` 应当一行不改地存活。若做不到,说明边界在别处已经漏了。
