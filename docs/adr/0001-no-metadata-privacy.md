# 不提供元数据隐私

本项目承诺的是 Content Confidentiality(服务端读不到 Session 内容),**不是** Metadata Privacy。Discovery Server 和 Relay 必然知晓"哪个 Peer 在何时与哪个 Peer 通信、通信量多少",我们接受这一点。

## 为什么记录这个决定

项目的核心诉求是"安全",未来的读者(包括几个月后的我们自己)看到 Discovery Server 能观察到完整的通信关系图时,一定会问"这不是漏洞吗"。它不是漏洞,是一个明确的范围决定。

## 考虑过的替代方案

提供 Metadata Privacy 需要洋葱路由 / 混淆网络 / 密封发送方 / PIR 之类的机制,代价是重写一个 Tor 级别的系统,并付出显著的延迟与复杂度。对一个传输核心的第一版而言,这个代价会挤占本该用在 Authenticity 上的全部预算——而 Authenticity 才是更容易做错、后果更严重的一环。

## 后果

- 任何对外材料都**不得**声称本项目提供"匿名"或"无法追踪"。措辞必须是"服务端无法读取通信内容"。
- 因为服务端**会**掌握通信关系图,所以这个服务端必须是自己的,不能是第三方的公共设施。见 [0002](./0002-transport-on-iroh.md) 的后果部分。
- 抗流量分析与抗审查(威胁模型中的 f)同样不在范围内,但传输层需要保留可加装混淆层的接口。
